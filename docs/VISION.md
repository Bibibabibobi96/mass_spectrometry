# 质谱仪仿真组装厂愿景

本页定义长期使命、目标能力和交付边界。实施优先级见[路线图](ROADMAP.md)，当前能力与证据见
项目`docs/PROJECT.md`和[集成状态](../integrations/docs/INTEGRATION.md)，任务入口见[README](../README.md)。

## 使命

将仓库建设为可持续扩展的**质谱仪仿真组装厂**：积累可复用的部件、物理模型和仿真能力，
让使用者能选择、配置和组合已有部件，研究单部件、局部装配或仪器，并在实际需求推动下补充缺失能力。
“组装”既包括几何与驱动，也包括粒子、场、气体、时间、接口和验证证据的连贯传递。

部件是有物理含义和验证边界的设计，不只是某个软件文件；同一部件可以有多个独立配置的实例。
项目维护设计及自身能力，跨项目组装引用这些权威。目录和实例规则见
[仓库架构](REPOSITORY_ARCHITECTURE.md#部件实例与组装)，连接语义见
[连接架构](COMPONENT_CONNECTION_ARCHITECTURE.md)。本页不建立另一套接口规范。

自然语言是表达需求与协作的一种入口；参数化设计、自动化运行、诊断和按需优化是实现这一使命的手段。
它们服务于可信的物理模拟，不作为每项部件研究或组装任务的前置完成条件。

## 使用闭环

```text
研究问题与所需证据
  → 选择已有部件和能力，识别缺口
  → 配置部件实例、组装关系、物理范围与边界条件
  → 冻结输入、分析指标和验收条件
  → 构建、求解、诊断与适用验证
  → 可追溯结果、限制或失败证据
  → 按实际需要完善部件或新增能力，再复用于其他组合
```

可以从单个部件开始，也可以研究已有装配的显式局部范围；局部结论只适用于已声明的边界。
使用者未要求优化时，默认目标是正确贯通和验证所需物理链。只有目标、指标与约束明确后，
才进入性能、结构或运行参数优化。

## 能力扩展方向

下表描述建设范围，不是当前已实现能力清单。每次研究只选择问题所需的物理，记录模型假设与未覆盖项。

| 方向 | 所需表达与证据 |
|---|---|
| 部件与几何 | 参数化设计、材料、电极、孔径、机械接口及可重建几何；不同实例保持独立身份 |
| 场与驱动 | 电磁场、静态或时变驱动、同步与作用域；明确边缘场和部件间场耦合 |
| 粒子与束流 | 离子／电子初态、轨道、传输、捕获、冷却及检测事件；保留来源、损失与统计口径 |
| 气体与真空 | 气体种类、温度、压力、边界与抽气条件；按适用流动区域扩展中性气体输运和分子流能力 |
| 相互作用与耦合 | 按研究需要引入碰撞、反应、空间电荷及其他耦合；给出模型来源、适用域和独立验证 |
| 系统结果 | 从部件到装配追溯传输、质量选择、时间／能量分布等指标及误差，明确未模拟的系统环节 |

给定背景气压下的碰撞轨迹、计算空间压力或中性气体流动、以及联立气体与带电粒子耦合，是不同能力。
存在压力字段或碰撞模型不能证明已求解气压分布或分子流；几何可组合也不能证明物理可耦合。
具体项目和工作流应在自己的状态页声明实际支持层次，而非从本表推定支持。

## 复用与增长

已有项目是逐步积累部件能力的基础，不要求先拥有完整仪器库才能开展研究。新增项目由真实物理需求、
独立设计和验证责任决定；已有项目能够承载的变体、工况和实例不重复建项目。
可复用机制在实际消费者验证后共享，避免为假想部件预建空目录、空接口或通用框架。

参考书、论文和供应商资料用于核对概念、模型与候选方向，不决定项目目录，也不自动成为参数基线。
资料入口见[学术参考资料](references/README.md)；项目划分仍以实际需求和复用边界为准。

## 可信结果与正式交付

运行成功、功能贯通、数值收敛、跨求解器一致及正式资格分别判断。部件的通过不自动授予组合后的系统资格；
系统中的某次通过也不扩大每个部件的独立适用域。

每项可引用结果应绑定需求、输入、实际模型范围、部件与实例身份、软件和数值设置、判据及来源记录。
正式交付按声明范围提供可重建模型、必要CAD、结果和验证报告，并满足
[GUI/CAD门禁](REPOSITORY_ARCHITECTURE.md#gui-与-cad-门禁)与[产物生命周期](LIFECYCLE.md)。
并非每项研究都需要全部求解器或正式发布；使用哪些工具取决于物理问题和验收要求。

仓库不保证任意组合、指标或制造约束都可实现。不支持、接口不相容、未收敛和物理负结果都是有价值的输出，
必须明确记录，不能靠替换输入、隐去损失或把准备成功当成求解成功来关闭任务。
未来能力不构成当前承诺；机器合同、当前状态与冻结证据共同限定每次运行能证明什么。
