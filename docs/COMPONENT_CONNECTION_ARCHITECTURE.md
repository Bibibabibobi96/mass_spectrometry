# 器件端口、连接器与跨项目联合模拟架构

本文是跨项目器件接口、连接与组装的唯一规范正文。具体连接参数、当前结果和资格由所属integration维护。

## 当前实施与迁移状态

跨项目装配使用仓库根`integrations/`、声明式配方和公共解析，目录与职责见下文[统一组装目标](#统一组装目标)。
组件提供者继续拥有物理设计、provided／required接口及自身资格，集成层不复制器件baseline或Formal资产。
新组合不再创建connection-family项目，也不以两个项目ID或connection profile替代显式实例与配方。
当前支持范围、真实运行及未闭合项由[集成状态](../integrations/docs/INTEGRATION.md)唯一记录；
历史链路保留冻结身份和证据，不因此保留已被替代的活动入口或兼容路径。

## 统一组装目标

本节是已批准、正在实施的迁移合同，不表示已经具备任意多组件组装能力。阶段与依赖见
[迁移路线](ROADMAP.md#统一组装迁移计划)，各参与方只在自己的PROJECT／INTEGRATION登记局部任务与证据。

### 固定目录和职责

跨项目组装的固定源码入口直接为仓库根`integrations/`，不再套一层`instrument_assembly/`，也不另建同名
顶层目录。该职责涵盖连接、几何装配、状态交接和联合物理工作流；在单一入口下不增加无独立职责的容器。
`integration_id=instrument_assembly`作为稳定的机器／产物owner，不要求源码目录与ID同名。
它不是硬件项目，不加入器件项目注册表；组件身份继续归原项目。
新组合通过配方表达，不再按组件组合、杆数、间隙或每次运行新增integration目录。
只有实际功能实施时才创建需要的目录，不预建空层，也不新增平行的顶层`assemblies/`。

```text
simulation_repo/
├─ projects/<project>/                 # 器件／仪器物理设计、提供者与自身资格
├─ common/contracts/                   # 公共组件、端口、装配与身份合同
├─ common/integration/                 # 求解器中立的解析、组装及校验机制
└─ integrations/                       # 固定入口；按实际功能创建下列职责目录
   ├─ README.md                        # 发现、能力边界与公开工作流导航
   ├─ config/
   │  ├─ recipes/                      # 装配配方
   │  └─ experiments/                  # 科学问题及工况；引用数值／运行合同
   ├─ workflows/                       # 按科学问题隔离的公开入口
   ├─ runtime/                         # 集成执行适配与共享编排
   ├─ analysis/                        # 联合分析，不复制器件分析算法
   ├─ tests/                           # 装配与工作流行为回归
   └─ docs/INTEGRATION.md               # 各配方／工作流的证据、限制与待办
```

仪器项目保留系统布局的物理约束、反射器／Prism／镜组设计、联合聚焦和自身验收；配方引用这些权威，
声明实际组件连接与装配，不在集成层维护第二套尺寸或工作点公式。跨组件结果归integration，
器件／仪器自身结论归PROJECT，集成通过不反写组件资格。通用机制只接收显式输入，不按OA、IP或MR
名称决定科学行为；公共化仍遵循[共享职责与依赖方向](DEVELOPMENT_STANDARDS.md#共享职责与依赖方向)。

### 配方、实验和工作流

配方是轻量、版本化的作者合同；它引用提供者并声明组件实例、变体选择、端口连线、直接刚体位姿、
连接器、驱动绑定和各连接的物理耦合模式。配方不携带运行路径、run ID、求解结果或复制的器件模型。
局部组件名加实例身份构成装配身份；同一项目可以出现多个实例，不能仅凭`project_id`去重。

每个实例分别绑定自己的提供者请求／resolved设计与工作点；同一提供者的不同实例可以采用不同尺寸、
结构变体、电压、RF频率／相位及气体条件，不修改项目全局默认来依次冒充多个器件。相同设计可以复用同一
提供者输出，实例位姿与驱动绑定仍各自独立；只有实际输入身份及适用边界相同的场资产才可复用。
电极和驱动以`instance_id + local_id`区分，求解器编号由该映射派生；不同实例的同名电极不表示电气短接，
共享电源或相位关系必须显式声明。各驱动使用同一仪器绝对时钟，允许自身频率、相位和时间规律，不强加
整机唯一RF工作点。以Q1、q2、Q3来自同一四极杆提供者、分别采用质量过滤／RF导引／质量过滤为架构检验；
这不表示当前workflow已实现三重四极杆物理运行，缺少相应提供者或执行能力时必须明确拒绝。

| 变化 | 唯一写入边界 |
|---|---|
| 新的组件连接拓扑、实例角色或端口关系 | 新配方，实验显式切换引用；不新建项目 |
| 已声明兼容的器件／结构变体替换 | 配方定义可选范围，实验选择；分别冻结实际拓扑和资格 |
| 电压、间隙、压力、源等既有合法自由度 | 实验行或其引用的唯一科学权威，交提供者／连接解析器派生 |
| 网格、时间步、数值分域 | 独立数值合同；不得改变机械／物理装配语义 |
| 新科学问题、物理假设或证据声明 | 独立workflow；复用既有组装、冻结、运行与分析机制 |
| 同一条件重新运行 | 新run身份，不生成新配方或源码目录 |
| 新的独立硬件设计概念 | 按仓库架构建立项目，发布组件接口 |

一个物理量只能在上述边界之一被人工定义；配方中的固定连接约束不能同时成为实验的另一份标量。
可替换项必须验证接口和物理适用域，不穷举杆数、变体与工况的笛卡尔积，也不能按文件名猜测兼容。
实验的变量和层次遵循[科学工作流与配置分层](DEVELOPMENT_STANDARDS.md#科学工作流与配置分层)；
公开workflow描述科学输入、输出与声明，不能为每个配方复制一套runner，或用万能Mode分支混合不同问题。

配方发现索引从实际配方生成，运行与资格索引从受管证据派生；不得人工维护第二份参数或结果表。
初期使用平坦组件实例与连接列表，不要求递归子装配框架。只有多个实际消费者需要同一完整子装配时，
才评估其独立端口和版本边界。

### 电压波形、器件驱动与同步

基础波形计算、器件电气定义和科学时序分别拥有唯一权威，不能由各项目重复实现同一波形，也不能把
器件状态机搬进公共层。实现按实际消费者收敛，公共化条件仍遵循上述共享职责规则，不预建万能波形引擎。

| 内容 | 唯一责任边界 |
|---|---|
| 已有真实需求的正弦／余弦、矩形门控及斜坡计算；相位、边沿与步长约束 | 仓库公共机制；不含器件名、电极编号或科学阶段图 |
| 电位参考、幅值约定、DC／RF／脉冲参数、电极绑定及物理限制 | 组件提供者的电气设计及其显式工作点 |
| 捕获、转移、抬升、淬灭、抽取等阶段及其触发条件 | 所属项目／科学workflow；调用基础波形，不复制其公式 |
| 跨组件触发、共享电源／相位关系及共同时间基准 | 装配实验及其冻结驱动绑定；不复制器件参数 |
| 将冻结驱动施加到实际场／电极及求解器时间步 | 求解器适配；不自行选择另一套电压、波形或时钟 |

恒定电压保留为普通数值，无须包装成动态波形对象。动态驱动直接从权威参数计算实际电压或已声明
单位响应的系数；静态贡献已在carrier中时只施加动态差分，不先施加绝对量再相减，也不重复叠加DC。
同类组件的不同实例分别消费自己的幅值、频率、相位和电极映射，不因共用kernel而共用一套驱动参数。

所有驱动消费唯一仪器绝对时间；释放位置、粒子批次、局部范围和恢复不能重新起算RF相位或脉冲时间。
各后端从同一冻结语义派生输入，明确秒／微秒、角度／弧度、峰值／峰峰值及电位参考，不各自维护同义标量。
矩形脉冲的有效区间统一为`[开始, 结束)`；公共机制提供下一边沿及适用步长限制，适配器结合各驱动的
限制选择实际时间步，不能跨过关键边沿而漏掉脉冲。理想跳变与有限上升／下降时间是不同物理输入，
必须显式区分，不擅自平滑、补偿或把数值时间步当作实际脉冲边沿。

先复用现有公共RF kernel，再收敛有实际重复消费者的脉冲／斜坡计算，不建立公式解释器、插件系统或
第二套驱动注册表。迁移保持既有科学阶段图和已冻结运行；跨后端验收至少核对同一绝对时间下的幅值、
相位、边沿左右值及分辨这些变化的数值设置。波形数学一致不代表场、轨迹或器件物理资格已通过。
当前实现范围、消费者迁移和验证证据归集成状态，不把本节目标写成已全部具备的能力。

### 完整装配、粒子源与局部求解范围

完整链路默认使用配方定义的完整物理装配；同一装配中的不同释放位置共用几何提供者、驱动绑定和执行机制，
不得按释放位置复制几何或另建runner。改变粒子源本身不删除部件、不关闭电压或碰撞、不重置仪器时钟。
完整装配不要求单一巨大PA或均匀细网格；求解器分域和多分辨率投影仍由数值合同表达。
作者未声明局部范围时即使用完整装配，无须重复填写完整范围开关。resolved计划与运行记录写明实际解析范围；
局部范围必须显式声明，声明无效或缺少必要边界时直接报错，不静默退回完整装配或沿用上次运行的范围。
完整性只相对于本次选定并冻结的配方：OA＋TOF可以是早期完整装配，加入多极杆、冷却部件或离子源后，
新增拓扑使用明确的新配方，实验主动切换引用后才扩大运行范围。不维护随时间扩张的全仓最大整机或额外的手工完整部件清单。
既有run的完整／局部含义绑定其原配方，后续扩展不改写旧plan或资格。若研究旧部件集合在新大装配中的
局部行为，建立引用新父配方的新run并显式选择该集合；不能仅因实例集合相同便认定场和边界等价。

实验必须显式引用所选配方；默认仅省略完整范围选择，不省略配方身份。禁止按目录发现、当前最大装配、
`latest`或上次运行自动选择配方。器件集合只在配方声明一次，完整运行不再重复列器件；启动前解析并冻结
实际配方、提供者输出与执行依赖，执行和续接只消费该次冻结输入，不重新读取活动配方。改变作者配方只影响
后续新run；不要求为每次普通修改另建版本目录或维护第二份版本注册表。

配方中的器件清单本身就是显式声明；实验不再维护第二份完整清单。增删实例、替换器件角色或改变连接拓扑，
应建立语义明确的新配方文件，并由实验显式改引用，不能在原引用下悄悄扩大或缩小拓扑。
同一拓扑下的合法尺寸、电压和数值调整继续由各自权威管理，不为每个数值组合新建配方。
旧配方有活动消费者时保留；无消费者时可按生命周期退役，历史run依靠自己的冻结输入追溯，
不要求永久保留旧生产入口或旧Schema执行分支。

重新执行当前作者实验与复跑历史冻结输入是两种不同操作：前者解析并记录本次实际输入，后者使用原run
冻结的配方、提供者、源、驱动、数值及执行依赖。只固定配方文件名不能承诺物理输入不变。
计划应直接列出实际实例、源实例、范围、边界、求解模式与预算，供排错与运行记录使用；
不新增手填拓扑指纹、重复哈希或一套独立版本账本，也不为每次启动增加人工确认。

实例ID表示可追溯的组件角色，不随显示名或列表顺序变化，也不因提供项目相同而合并。删除、改名、替换
组件或修改frame后，源、连接、驱动和观测引用必须重新解析；悬空或不适用的绑定直接报告具体实例和缺项，
不自动猜测替代对象。局部清单采用显式包含的实例ID，不使用随父配方增长而自动扩张的排除清单。

full只表示选定配方全部实例均在范围内，不表示已有足够物理能力或资格。workflow在昂贵构建／启动前检查
本研究实际需要的组件接口、场与驱动覆盖、源及观测面；不按配方总实例数硬编码完整性，也不静默忽略新实例。
不支持的组件或局部边界应明确拒绝，并指出尚缺的执行能力。新增组件可能改变边缘场、网格规模与运行预算，
须重新解析相应输入和预算；旧场和资格仅在其已验证适用条件内复用，不能因源位置未变自动继承。
关闭某组件的驱动并不移除其几何、接地屏蔽或碰撞作用；移除组件则是范围或拓扑变化，不能用零电压冒充。
局部范围切断连接时须有适用的边界与耦合声明，不自动补齐未选组件或把连通检查当成场等价证明。
组件顺序、显示名、求解器电极编号和执行批次均不得承担物理身份；并行、分域或分段执行仍须保留同一
实例映射、粒子身份与仪器时钟。跨装配或数值条件的结果比较须声明实际差异，不能只比较full标签。

装配、源、物理驱动与数值设置各有唯一权威，局部求解范围另行显式声明。源须包含完整初始状态及来源，不能只给位置：作者定义的新出生群、
实测出口交接和已记录状态重启各自保留真实语义，共用canonical状态投影与原生启动机制。
交接／重启保留原ID、绝对时间、母群和上游损失；不能将下游重新定义的群体报告为完整上游传输。
涉及RF、脉冲或碰撞时，继续消费对应时间基准和适用的状态，不能用移动出生位置替代上游演化。
组件内源绑定稳定实例ID及其局部frame和完整初始状态；不以完整／局部标签选择另一份源，也不以项目名
代替可能重复的组件实例。同一OA实例内的源可用于包含它的完整或局部范围，装配层仅应用该实例的唯一位姿，
不因范围选择移动、裁剪或重采样源。所选范围缺少源实例时明确报错；场域、边界和观测条件仍须满足实际研究，
例如只有OA的局部飞行不能生成TOF检测器资格。求解器状态交接仍保留实际frame和clock，不另加源位置补偿。

求解器可以使用提供者局部frame作为工作frame；父配方仍保留原装配frame和直接位姿，不要求该器件位于父原点。
器件、场采样与源使用同一公共相对变换，从已声明的组件位姿直接投影到工作frame；数值域必须明确属于该frame。
原状态已在工作frame时直接使用，不通过矩阵往返移动它；已记录状态的frame须由冻结来源证明，不能从父frame名称或范围标签猜测。

局部求解只作为显式研究范围，从同一完整装配及其提供者resolved输出派生；不维护独立尺寸、电极、位姿或
另一份可编辑子模型。局部范围声明所选部件／数值域、边界与耦合假设及观测范围，结果绑定其父装配和实际源。
不按释放位置自动裁剪部件，也不自动认定上游边缘场可忽略。局部验证只支持声明范围内的结论，不能授予
完整链路资格；需要近似等价声明时，对照范围和数值证据须覆盖该近似。

仅改变源而未改变几何、材料、边界条件、网格和单位场定义时，复用同一已发布场资产；RF／脉冲运行系数仍
由实际驱动与时钟计算。该复用只适用于场不依赖粒子群的模型；若实际采用空间电荷等自洽耦合，源改变后
按该模型重新求解，不能沿用测试粒子近似的结论。不为单纯切换释放位置重复求场、复制大PA或另建缓存身份。已有独立局部workflow须在
同源派生替代完成后退出重复实现；尚未迁移的活动流程保留明确边界，不把此目标写成当前已全部具备。

器件性能验收与实测状态有效性分别判断。已完整结束、身份与母群闭合且状态通过校验的运行，即使
捕获率等性能指标未达标，也可发布真实出口供下游研究；交接必须携带原科学状态、验收结果及全部上游损失，
不把它改为器件验收成功。执行未完成、数据身份或闭合失败的输出不能交接；零出口不能启动下游飞行。
提供者设计／场的兼容性检查只绑定实际相关的几何、驱动、物种及数值条件，不要求新的源定义等于旧设计源。

### 演进时的稳定性与失效边界

保留“实验显式选配方，省略局部范围即运行该配方全部实例”的唯一默认规则。
要求每个实验再列一遍完整器件不会固定提供者、工作点或数值条件，反而增加清单漂移与漏件的来源；
显式性落实在配方选择和配方内的实例声明，不增加同义的完整模式开关或实验器件白名单。

| 范围方案 | 收益 | 代价与取舍 |
|---|---|---|
| 显式配方，默认全部实例；局部显式包含 | 器件集合只定义一次；新增拓扑经切换配方进入实验；配置最少 | 必须区分重新运行作者实验与复跑冻结输入；采用此方案 |
| 配方之外，每个实验都列完整器件 | 打开实验即可看到集合 | 两份清单易漂移；仍不能固定提供者、驱动和边界，不采用 |
| 每个完整或局部集合都维护独立配方 | 每个集合有直接名称 | 局部位姿、连接和参数重复维护，容易与父装配分叉；仅独立物理拓扑使用新配方 |

默认全部实例的代价是真实新增部件可能增加求场、内存和运行成本；这个代价由显式配方切换、数值分域及
预算承担，不通过按源位置自动删部件解决。只想研究局部时声明局部范围即可，不再增加第二种默认规则。
同一配方引用也不能单独保证长期输入不变：提供者参数和实现仍会演进；精确复跑以既有冻结输入为准。

完整／局部是相对于所选配方的派生描述，不是器件集合的永久等级，也不用于自动选择源、资产或统计分母。
旧OA＋TOF配方仍是自己的完整装配；在新多极杆＋OA＋TOF配方中选择OA＋TOF才是新的局部研究。
这两个运行即使器件名字相同，也不能自动共享局部边界或物理资格。
物理范围选择与数值分域分别解析：完整装配可以使用多个数值域，使用局部细网格不等于删除域外器件。
不按源位置、粒子预期路径或域的数量推断物理范围；排错时直接查看解析计划中的实际实例与边界。

完整物理装配与粒子经历的过程分别记录。在完整多极杆＋OA＋TOF几何内从OA新释放离子，
只能证明该源开始后的行为；不能据此声明多极杆输运、冷却或离子源效率已验证。
统计分母和结论范围由真实母群、来源和事件链决定，不由full标签决定。
源在组件局部frame内保持定义不变；组件位姿改变时，其装配坐标随唯一位姿正常变化，不承诺旧世界坐标不变。

| 实际变化或故障 | 处理边界 |
|---|---|
| 增删组件、改变连接或实例角色 | 新配方及实验主动切换；旧run保持原完整／局部含义 |
| 局部声明为空、字段拼错、实例重复或引用不存在 | 在输入解析处拒绝并报告字段或实例；只有未提供局部声明才使用默认完整范围，不能把无效声明当作省略 |
| 提供者结构、端口、frame或驱动接口改变 | 按声明的接口和适用范围重新解析；不兼容时报告具体绑定，不猜旧值或替代实例 |
| 同拓扑尺寸、位姿、材料、电压或气体改变 | 从其唯一权威重新派生受影响输入，核对场、边界及资格适用性；配方名相同不代表物理等价 |
| 源、质量／电荷、出生时间或状态来源改变 | 检查所选组件、模型及时钟的接受条件；保留出生、交接、重启差别，不借改变源省略上游损失 |
| 数值分域、重叠优先级、精度或规模改变 | 从同一物理装配解析数值覆盖、耦合与预算；容量不足明确停止，不自动删部件、降精度或换物理模式 |
| 场资产缺失／不适用或求解器能力不支持 | 指明缺失资产或能力；需要重建则按正常新run执行，不把残留文件、历史资格或部分输出当作成功 |
| 新部件改变气体、自洽场或组件间耦合 | 按实际模型重新核对物理覆盖及场复用；几何接口兼容不代表旧物理模型仍适用，不静默保留孤立器件近似 |
| 构建或某执行分段失败，只产生部分输出 | 保留真实失败及已完成证据，按既有生命周期收尾；不发布完整成功或由残留文件推定后续阶段完成 |
| 比较不同年代的完整运行 | 比较冻结的实际组件、源、驱动、边界、数值条件及真实母群；full标签、配方名或检测粒子数相同不构成同工况 |
| 在途修改、进程中断或历史复跑 | 在途只用冻结输入；按既有生命周期处理终态／新run，复跑核对实际工具能力，不悄悄混入当前实现 |

冻结记录保证历史输入可追溯，不承诺任意未来软件都能执行旧合同。遇到不支持的输入格式、缺失依赖或
不兼容工具时明确停止；确需迁移的历史实验建立新run并记录与原输入的差异，不为此永久保留旧执行分支。
同样输入在不同求解器版本或随机执行策略下也不自动承诺逐粒子逐值一致，结果比较应采用相应研究的验收判据。

这些检查在已有解析器、提供者接口、执行前检查和发布边界实现，各边界只负责自身输入；
不新增通用插件平台、并行版本账本、重复大文件哈希或自动迁移回退系统。
运行前展示的实例、源、范围、场模式与预算直接来自实际执行计划，不能另造一份人工摘要成为权威。
解析、容量准入、资产选择与执行消费同一份冻结计划；不能在展示或预算检查之后重新解析活动配方，
使实际执行悄悄改变。需要修改输入时建立新run，沿用既有冻结机制，不增加第二套锁定文件。
源实例存在只是绑定有效的必要条件；观测器件被局部范围排除、源状态不被实际模型接受或必要驱动缺失时，
报告具体缺项，不能仅凭源位置合法就启动并发布原研究的成功结论。
演进验收优先覆盖上述会改变结果含义的情况，不为尚无消费者的未来物理能力预建实现。

### 组件接口与装配编译

提供者拥有器件内部拓扑和需求解析。消费者通过显式、版本化接口请求组件，不读取私有字段重画几何。
最小接口语义如下；具体字段和版本由公共Schema与校验器定义，各阶段实际支持范围见集成状态。

| 输出或绑定 | 必须表达的语义 |
|---|---|
| 身份与来源 | 提供项目、API版本、结构profile／variant、请求与实际依赖身份；区分模型能力和已验证范围 |
| 局部几何 | 带稳定局部名称的实体、电极、孔、屏蔽、真空和必要材料；显式区分实体、零厚理想面与数值边界 |
| 坐标与端口 | 局部frame、单位、provided／required端口、方向、孔径、参考面与接受条件 |
| 电气驱动 | 具名电极及驱动通道，DC／RF／脉冲的权威引用、电位参考、幅值约定、频率、相位及时间基准 |
| 其他物理 | 适用的气体区域、压力／温度、碰撞模型等；不适用须明确，不静默补为真空 |
| 源与事件 | 引用公共释放／canonical状态与事件合同，保留母群、谱系、损失、frame和唯一仪器时钟 |

几何和驱动可分开发布并由身份绑定，不要求把所有内容复制进一个文件；局部PA编号、GEM或MPH可作为
派生投影，不能成为全局电极身份或唯一几何权威。提供者给出的孤立器件电压／焦点只是声明范围内的
工作点；装配后的场、能量和聚焦必须按系统条件验证，组装器不自动优化或反写提供者baseline。

编译链为`配方 + 实验及其权威引用 → 提供者resolved输出 → 冻结装配与composition plan → 求解器/CAD投影`。
优先扩展现有composition plan及resolved合同，明确多实例、多连接和逐连接耦合模式，不并行建立同义计划。
每个实例只声明一份从提供者局部frame直接到唯一装配frame的刚体位姿。几何和粒子状态分别只应用
这份位姿一次，速度只旋转；源自身的坐标表示转换由源提供者声明，在消费边界明确组合后一次应用。
禁止沿连接链递推或反算组件位姿、增加补偿偏移、重复翻转轴向，或用另一处误差抵消错误的端面定义。
端口检查直接使用同一装配frame中的真实端面中心和外法向：下游端面应等于上游端面沿其外法向移动
显式非负间隙的位置，两端外法向应相反。检查失败时修正产生错误的唯一输入或提供者定义，不放宽容差
迁就错误装配。矩形开口须区分外壁面与壁中面；裸杆自由空间包络不是实体孔径或粒子接受边界，不能
由金属共模电位推定整个开口面电位。求解器坐标投影必须显式记录，不引入第二份可调装配位姿。

电极以实例和局部名映射至求解器编号。时钟遵循
[公共时钟权威](DEVELOPMENT_STANDARDS.md#canonical-instrument-clock-authority)，旧端口的秒／offset表示
须在迁移适配边界显式核对并转换，不能直接当作canonical微秒或建立第二epoch。

统一物理装配保留部件与电极身份，不等于把不同电位实体合并，也不强制使用一个巨大网格。
整体场、局部细场或状态交接必须从相同装配及声明模式派生，不能仅拼接独立场文件宣称联合求场完成。
编译前检查身份／单位／frame／clock及驱动一致性，编译后检查实体关系、通道、参考面和场责任覆盖。
端口校验、包围盒或有限采样不能冒充完整几何净距验收；检查范围和未验证关系必须显式报告。

### 切换与在途运行保护

代码迁移已获批准；入口、依赖、求解与退役按下列逐workflow验收执行。未完成切换的项目和integration
继续按活动合同运行；暂停的科学工作不因迁移计划登记而自动恢复。

后续实现须按workflow分别列出来源入口、目标配方、依赖和关闭证据；现有注册Schema的
`integrations/<id>`路径约束也须显式迁移为直属根布局，不能只移动文件或伪造硬件项目登记。
先以同一冻结物理输入完成相称
合同／几何投影／真实求解行为对照，再同步切换调用者、注册、门禁路由与文档。目录改名不授予物理资格；
新增物理能力与等价迁移分别验收，不能把尚未贯通的真实多极杆→IP链写成迁移成功。

切换不得移动、覆盖或删除在途run、冻结输入、源码闭包、PA/MPH、GUI包、缓存和租约。若运行仍依赖
工作树中的源文件，须等该依赖释放后再改动相关路径，不能假定所有运行已完全隔离。已冻结运行继续
原身份至终态；需要重启时按正常生命周期建立新run，不为迁移另设恢复状态机。
某workflow完成切换后，新请求只走目标入口；旧生产副本在无在途依赖且替换门禁通过后退出。
未切换workflow仍保留原入口，不得将整个旧目录提前标成只读或退役。产物归属和历史保护只按
[统一组装产物归属](LIFECYCLE.md#统一组装产物归属)执行。

## 连接器归属

| 类型 | 归属 |
|---|---|
| 零长度canonical状态交接 | 公共端口与composition合同 |
| 通用无源圆筒、矩形管、接地孔primitive | `common/integration/`或已验证公共几何层；实例值在connection profile |
| 某一连接族专用实体或场重叠区 | 对应integration |
| 具有独立电极、脉冲、透镜或可独立验收功能 | 建立独立项目并发布端口 |

连接profile至少声明mating ports、孔径、壁厚、材料、电位、位姿、场耦合、网格职责和观察面。
解析器必须对坐标/时钟不一致、实体相交、未定义真空、电位冲突、场域重叠或缺失、物理面语义混同和
求解器投影不一致失败关闭。

## 联合模拟模式

profile显式选择一种物理模式：

1. `state_handoff`：上游输出canonical状态，下游重新释放；
2. `field_overlap`：integration拥有连接区联合场；
3. `monolithic_joint_solve`：器件与连接器在同一模型中求解。

执行策略是运行实现，不得与物理模式混淆。例如一个`monolithic_joint_solve`连接可在SIMION采用
同一次Fly连续飞行，并用checkpoint记录中间状态；checkpoint不是state handoff。

## SIMION粗全局PA与局部细PA耦合

当一个连续SIMION装配中只有局部器件需要更细网格，而整体细化会改变其他器件的离散场、超过内存
预算或显著增加构建时间时，可使用“粗全局PA + 局部细PA overlay”。这是一种
`monolithic_joint_solve`的数值实现，不把粒子导出、重新释放或时间清零。

采用该模式必须同时满足以下合同：

1. 粗PA覆盖完整物理装配和全部连续飞行路径；局部PA只重建其负责的实体，坐标、尺寸和电极ID来自同一
   resolved geometry，不维护第二套物理参数。
2. 对粗PA的每个可调电极建立独立单位基函数，把六个局部外表面的粗场电势逐点复制为细PA的Dirichlet
   电极边界；运行时按同一电极电压线性组合。只复制当前合成电势不能支持RF、脉冲或fast-adjust变化。
3. 人工Dirichlet面是SIMION数值电极，不是透明接口。完全位于不可通行实体导体内的面可以贴合该导体；
   存在孔、透明栅网或粒子通道的面必须越过物理结构并保留重叠保护区。局部实例须在粒子到达人工面前
   失活，使粗PA接管；不得让出口人工面与透明栅网重合。
4. Workbench中局部PA置于粗PA之后并具有更高覆盖优先级；`instance_adjust`只在声明的内部有效域启用
   局部实例，在保护区外回退到粗PA。两套PA仍在同一次Fly中使用同一粒子、绝对时钟和电压调度。
5. 首次启用必须先跑同网格身份对照，再改变局部网格。同网格对照至少检查逐阶段census、共同粒子的
   checkpoint状态、探测TOF和落点；只验证六面电势相等不足以证明实例切换没有改变轨迹。
6. PA族按几何、网格、粗PA、电极映射、基函数构建器、Refine机制和SIMION身份建立内容寻址缓存。
   基函数默认串行构建；SIMION并发只有在独立资源测试证明内存、写盘、许可证和稳定性均有余量后才能
   开启。缓存是可删除性能层，run仍冻结输入、验证报告和所用PA身份。

本节描述耦合设计和验收边界，不维护公共代码消费者数量或当前物理资格。
已存在的无器件假设 PA 构建与场比较机制直接复用[公共 SIMION 实现](../common/simion/README.md)。
器件局部域、portal、实例启停和接受阈值仍由消费者拥有；不能重新建立公共构建器的项目私有副本。

## 扩展门禁

以下门禁约束现有机制的连接扩展；目标架构的新组合按[配方规则](#配方实验和工作流)进入固定入口，
不再为组合创建第二个integration。迁移期新增连接profile同样必须：

1. 两端发布版本化端口；
2. 冻结连接profile和唯一变量；
3. 生成并验证resolved connection与composition plan；
4. 两端求解器从同一resolved连接投影；
5. 以同一源完成静态、功能和相称的数值验证；
6. 形成integration文档、changed-scope路由和artifact身份；
7. 将被取代过程冻结为history，再按授权退出旧活动入口。

仅创建schema、空目录或静态PASS不构成联合物理资格。
