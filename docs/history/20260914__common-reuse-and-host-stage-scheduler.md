## 调度器实际行为与边界

PowerShell租约文件负责采样、申请、等待和释放，Python主机调度器负责唯一原子准入与SQLite账本；
两者是接口与核心，不是两个独立资源所有者。不同工作树共用机器级账本，不保留旧全机mutex协议。
SIMION原内部规划器仍负责粒子/独立工作拆分和自身运行保护；它与主机核心共享阈值，
但本轮没有完成所有内部worker规划按有限父预算裁剪的改造。

阶段先声明CPU核数、内存、批量I/O槽与具名独占资源，取得许可后才能启动。
准入同时检查已承诺但尚未驻留的内存、实际压力和保留内存，避免仅凭当下空闲率超配。
阶段切换重新排队；普通工作子进程未结束不能降预算。PID加启动身份防止PID复用误归属；
父进程退出但工作子进程活着时保留占用。精确系统conhost不阻止已完成阶段释放。

未知峰值采用保守独占；观测缺失失败关闭。旧快照不得覆盖新事务，冲突后重新采样并随机退避；
进入队列后允许有界越过，达到8次即构成队列屏障。进入队列前不保证强公平或最大等待时间。
退避与CIM采样会增加等待，取消不保证即时响应。

| 当时实际任务组合 | 准入情况 |
|---|---|
| expected_values_tests、ruff_all、ruff_changed_python之间 | 已标定的小阶段可共享，仍受总预算限制 |
| 小阶段与任何unknown阶段 | 不能并行 |
| MR准备、飞行、后处理与其他任务 | 三阶段均unknown，分别独占；campaign行间可释放 |
| OA single-flight | 仍经SIMION/unclassified入口，unknown独占 |
| 大多数项目静态回归、默认COMSOL/SIMION阶段 | unknown独占 |
| 两个需要同一具名COMSOL session的阶段 | 不能并行 |
| 同一SIMION运行内独立批次/PA工作 | 依原内部规划规则可并行，不等于跨项目并行 |

控制范围只实现单机阶段准入、统一资源合同和既有入口接入；下一步应基于实际工况标定阶段，
并约束内部worker使用已获预算。没有证据时不新增泛化调度层或激进并发档。
预算是准入承诺，不是OS硬限额；当前机制不会自动杀死超预算科学进程，也不能保证运行中绝不超用。
多数科学阶段仍独占，因此尚不能宣称吞吐提升，部分门禁可能因更保守的串行和采样而变慢。
